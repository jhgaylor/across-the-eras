SKIPTO.TV + YOUR AI

Ask your assistant instead of clicking.

Every chart, vibe and guest-cast filter on this site is also available to Claude, ChatGPT and any other assistant that speaks MCP. No account, nothing to install — you paste one web address into your assistant and it can look things up for you.

What this is, in one paragraph

Under the hood, this website is a big pile of hand-curated facts about a handful of TV shows: who was showrunning when, which Big Bad each season had, which episodes are gut-punches, which guest star showed up where. The MCP endpoint lets an AI assistant read those same facts and run those same filters. So instead of clicking "Season 5 → Glory → Gut-punch", you can just ask "which Buffy episodes from the Glory season are the sad ones?" and get an answer — with a link that opens the site with those exact filters applied.

The address to give your assistant:https://skipto.tv/mcp

MCP stands for Model Context Protocol — an open standard that lets an assistant use tools on a website, a bit like a plug-in. You don't need to know more than that. Lookups are read-only. A show proposal can open a public review request, but it cannot publish or merge anything.

What you can ask

Anything the site can filter, in plain English. Some examples that work well:

"What are the best-rated standalone Supernatural episodes from the Kripke years?"
"I'm rewatching Buffy and I've seen everything through 3×07. What's next?"
"Which Criminal Minds episodes have Gideon and are two-parters?"
"Pick me a random Doctor Who episode with Donna, rated 8 or higher."
"Which Angel episodes does Faith turn up in? Give me a link."
"Which shows do you have? Show me the era chart for The Wire."
"Add Severance to skipto.tv. Research it, show me what you found, then submit it for review."

The assistant will usually reply with a short list and a link like https://skipto.tv/buffy/#s=5&t=heavy. Click it and the site opens with those filters already on, so you can keep exploring by hand.

Fastest way: let the assistant set itself up

Most assistants can add a connector if you just tell them to. Copy this and paste it into a new chat:

Please connect to the "skipto.tv" MCP server so you can look up TV rewatch guides for me.

Server URL: https://skipto.tv/mcp
Type: remote MCP server, Streamable HTTP transport
Authentication: none (leave OAuth / client ID / secret blank)

If you can add it yourself, do that. If it has to be done in settings, tell me exactly where to click and what to paste. Once it's connected, call list_shows and tell me which shows are available.

Whether the assistant can do this on its own depends on the app: Claude Code and most coding tools can; claude.ai and ChatGPT will walk you through the settings screen. Either way it saves you hunting for the right menu.

Connect it by hand (about a minute)

Claude (claude.ai and the Claude desktop app)
  1. Open Settings → Connectors (on claude.ai) or Settings → Connectors in the desktop app.
  2. Click Add custom connector.
  3. Name it anything (e.g. skipto.tv) and paste https://skipto.tv/mcp as the URL. Leave the OAuth/authentication fields empty — none is needed.
  4. Save. In a new chat, make sure the connector is switched on (the tools/attachments menu), then just ask.
ChatGPT
  1. Go to Settings → Connectors (custom connectors need Developer mode turned on under Settings → Connectors → Advanced, or a workspace admin to enable them).
  2. Choose Create, give it a name, paste https://skipto.tv/mcp, set authentication to None.
  3. Start a chat, open the tools menu and enable the connector, then ask away.

Availability of custom connectors depends on your ChatGPT plan; if you can't find the option, that's why.

Cursor, Windsurf, VS Code, Claude Code and other developer tools

Add this to the tool's MCP config (the file is usually called mcp.json or lives under a "MCP servers" setting):

{
  "mcpServers": {
    "skipto-tv": { "url": "https://skipto.tv/mcp" }
  }
}

Or, in Claude Code:

claude mcp add --transport http skipto-tv https://skipto.tv/mcp
Anything else that supports MCP

Pick "remote server" / "HTTP" / "Streamable HTTP" as the type, paste the address, no authentication. If the tool asks for an SSE URL specifically, it's using an older flavour of MCP that this server doesn't speak — most tools updated during 2025.

What the assistant can actually do

These are the "tools" the assistant sees. You never call them yourself — this is just so you know what's possible (and what isn't).

ToolWhat it does
list_showsWhich shows exist here.
get_showThe full era chart for a show (every bar, with its seasons), the list of vibes, the seasons and their showrunners, the most frequent guest characters. The assistant reads this to learn the vocabulary before filtering.
find_episodesThe main one. Filter by season, chart bar (era/arc/Big Bad/roster/location…), vibe, guest character, free text, minimum rating; sort by air date or rating. Returns the matching episodes and a link that opens the same filters on the site.
get_episodeEverything about one episode: summary, rating, air date, vibes, the complete guest cast, and its "what's going on" context (who's showrunning, which Big Bad, which arc), plus previous/next.
search_charactersFind a recurring guest character by (part of) their name — who played them and which episodes they're in.
surprise_meOne random episode matching your filters. Same as the 🎲 button.
next_episodeTell it what you've already watched (episode codes like S03E07) and it returns what's next — optionally within an arc or vibe.
share_linkJust build a link to the site with a set of filters (and optionally an episode card) open.
get_submission_guideLearn the research, sourcing and data requirements for proposing a missing show.
submit_showAfter showing you the researched package and getting confirmation, validate it and open a public pull request for maintainer review. It cannot publish or merge.

Things worth knowing

It's exactly the site's data

The tools run the very same filter code the website runs, on the same files. If the assistant says "12 episodes", the site's counter says 12 too.

No account, no memory

Your "watched" ticks on the site live in your own browser and never leave it. If you want the assistant to know what you've seen, tell it in the chat — it passes that list along with each question and forgets it afterwards.

Series regulars vs guests

Guest-character search covers guest cast (from TVmaze). The main cast usually aren't listed per episode; for them the assistant uses the roster rows on the chart instead. It knows this, but if a search comes back empty, that's usually why.

Fuzzy is fine

You can say "Glory" instead of "Glory, the Beast", or "gut punch" instead of the exact vibe name; the tool matches loosely and tells the assistant when something was ambiguous or unknown, so it can ask you.

What we log

Anonymous counts of which tools get used for which show, same as the site's own page analytics. No chat contents, no identities.

Proposals are reviewed

A show submission creates a public proposal, not a live page. The server accepts data rather than code, CI checks the generated files, and a maintainer decides whether to merge it. Its notes and sources are public, so don't include personal information.

For the technically curious

  • Transport: MCP Streamable HTTP, stateless (no sessions), no auth. GET /mcp in a browser returns a small JSON banner.
  • Also exposed as MCP resources: skipto://shows, skipto://shows/{slug}/chart, skipto://shows/{slug}/tags, skipto://shows/{slug}/episodes — for clients that prefer to pull a whole show into context.
  • The filter engine is one shared file, filter.js, loaded by both the browser and the server. Source and the per-show data format live in the GitHub repo.
  • Want a show added? Ask your connected assistant to research and propose it. It will show you the work and ask before opening the public PR. You can still open an issue for smaller corrections.
